# hangul-willow 프로젝트 구현 명세

## 1. 프로젝트 한 줄 정의

`hangul-willow`는 능수버들 아래에서 한글 글자들이 바람과 함께 흩날리는 정적 웹 기반 인터랙티브 캔버스 작품이다.

입력은 현대 한국어 문장으로 받되, 화면에 떠다니는 출력은 중세국어풍 옛한글 조합 자모와 방점 느낌을 섞어 렌더링한다.

## 2. 프로젝트 목표

### 핵심 목표

- 브라우저에서 바로 실행되는 한 화면짜리 인터랙티브 작품을 만든다.
- 사용자가 입력한 한국어 문장에서 글자 풀을 만든다.
- 글자 풀을 중세국어풍 시각 토큰으로 변환한다.
- 변환된 글자 토큰이 능수버들 잎처럼 화면에 흩날리게 한다.
- 바람, 밀도, 일시정지, 재시작 정도의 간단한 조작을 제공한다.

### 감성 목표

- 화면은 조용한 밤 풍경처럼 보여야 한다.
- 글자는 낙엽, 종이 조각, 작은 빛 조각 사이 어딘가의 느낌으로 움직인다.
- 중세국어풍 출력은 읽기보다 감상하는 대상에 가깝다.
- 컨트롤 패널은 작품을 방해하지 않고 조용히 떠 있어야 한다.

### 기술 목표

- 빌드 도구 없이 `index.html`을 직접 열어 실행 가능해야 한다.
- 외부 패키지 없이 HTML, CSS, JavaScript만 사용한다.
- 캔버스 2D API로 배경, 버들, 잎, 글자를 모두 그린다.
- UI 컨트롤은 캔버스 내부가 아니라 HTML DOM으로 만든다.
- 구현은 단일 파일이 커져도 이해 가능한 함수 단위로 나눈다.

## 3. 비목표

- 중세국어 문장 번역기를 만들지 않는다.
- 역사적으로 정확한 음운 변환을 보장하지 않는다.
- 학습 앱, 사전 앱, 문법 분석기를 만들지 않는다.
- 여러 페이지로 구성된 웹사이트를 만들지 않는다.
- 서버, 데이터베이스, 로그인, 저장 기능을 만들지 않는다.
- 복잡한 설정 패널이나 튜토리얼을 만들지 않는다.
- 초기 버전에서는 WebGL, Three.js, 물리 엔진을 쓰지 않는다.

## 5. 사용자 경험

### 첫 진입

사용자가 `index.html`을 열면 바로 작품 화면이 보인다.

첫 화면 구성:

- 전체 화면 캔버스
- 어두운 녹색과 남색 계열의 밤 배경
- 은은한 달과 달빛 번짐
- 오른쪽 또는 상단에서 내려오는 능수버들 줄기와 가지
- 천천히 떨어지는 잎
- 중세국어풍으로 보이는 한글 글자 입자
- 화면 오른쪽 아래의 컨트롤 패널

### 기본 문장

초기 입력값:

```text
달빛 아래 한글이 바람을 따라 흐른다
```

사용자는 이 문장을 지우거나 바꿀 수 있다.

### 사용자가 할 수 있는 일

- 문장을 입력해서 흩날리는 글자의 재료를 바꾼다.
- 바람 세기를 조절해서 좌우 움직임을 바꾼다.
- 밀도를 조절해서 글자와 잎의 양을 바꾼다.
- 멈춤 버튼으로 장면을 정지한다.
- 다시 흩날리기 버튼으로 입자 배치를 새로 만든다.
- 마우스나 포인터를 움직이면 근처 글자가 살짝 밀려난다.

### 사용자가 보지 않아야 할 것

- 복잡한 설명문
- 개발자용 로그
- 빈 화면
- 네모 박스로 깨진 글자가 화면 대부분을 차지하는 상태
- 입력창 텍스트가 자동으로 이상한 옛글자로 바뀌는 상태

## 8. 앱 상태 모델

전체 앱 상태는 하나의 `state` 객체로 관리한다.

```js
{
  width: 0,
  height: 0,
  dpr: 1,
  glyphs: [],
  leaves: [],
  phrase: "",
  wind: 0.46,
  density: 92,
  paused: false,
  lastTime: performance.now(),
  sceneTime: 0,
  pointer: {
    x: 0,
    y: 0,
    active: false
  }
}
```

### 필드 설명

`width`, `height`

- CSS 픽셀 기준 캔버스 크기
- `window.innerWidth`, `window.innerHeight` 기반

`dpr`

- `window.devicePixelRatio` 기반
- 최대 2 정도로 제한해 성능을 보호한다.

`glyphs`

- 한글 글자 입자 배열
- 각 입자는 글자, 방점, 위치, 속도, 크기, 투명도, 회전 정보를 가진다.

`leaves`

- 잎 입자 배열
- 각 입자는 위치, 크기, 낙하 속도, 흔들림 정보를 가진다.

`phrase`

- 입력창의 현대어 문장
- 이 값 자체는 중세국어풍으로 바꾸지 않는다.

`wind`

- 0-1 사이 값
- UI 슬라이더 0-100을 100으로 나눈 값

`density`

- 글자 입자 개수의 기준값
- 잎 개수도 이 값에 비례해서 만든다.

`paused`

- true일 때 장면 시간과 입자 업데이트를 멈춘다.

`lastTime`

- 직전 animation frame 시각

`sceneTime`

- 실제 애니메이션에 사용하는 누적 시간
- 일시정지 중에는 증가하지 않는다.

`pointer`

- 마우스나 터치 포인터 위치
- 근처 글자를 살짝 밀어내는 데 사용한다.

## 9. 데이터 모델

### GlyphToken

입력 문장에서 만든 출력용 글자 토큰이다.

```js
{
  text: "ᄒᆞᆫ",
  tone: 1
}
```

`text`

- 캔버스에 그릴 문자열
- 현대 한글 한 글자일 수도 있고, 옛한글 조합 자모 묶음일 수도 있다.

`tone`

- 방점 개수
- `0`, `1`, `2` 중 하나

### GlyphParticle

화면에서 움직이는 한글 입자다.

```js
{
  text: "ᄒᆞᆫ",
  tone: 1,
  x: 420,
  y: 180,
  originX: 420,
  originY: 180,
  vx: 8,
  vy: 22,
  size: 32,
  alpha: 0.72,
  rotation: 0.4,
  spin: -0.1,
  sway: 3.8,
  warm: false
}
```

`text`, `tone`

- `GlyphToken`에서 온 값

`x`, `y`

- 현재 위치

`originX`, `originY`

- 초기 위치
- 지금 당장 쓰지 않더라도 추후 복귀 애니메이션에 사용할 수 있다.

`vx`, `vy`

- 기본 이동 속도
- `vx`는 바람과 흔들림에 더해진다.
- `vy`는 낙하 속도다.

`size`

- 글자 크기
- 권장 범위 17-52px

`alpha`

- 투명도
- 권장 범위 0.34-0.92

`rotation`, `spin`

- 현재 회전값과 회전 속도

`sway`

- 각 입자의 흔들림 위상

`warm`

- 강조 색을 사용할지 여부

### LeafParticle

잎 입자다.

```js
{
  x: 100,
  y: 200,
  size: 8,
  speed: 18,
  sway: 1.4,
  alpha: 0.24
}
```

잎은 글자보다 배경에 가까운 레이어다. 너무 선명하면 글자와 경쟁하므로 낮은 투명도를 유지한다.

## 10. 중세국어풍 출력 설계

자세한 내용은 [middle-korean-output-plan.md](./middle-korean-output-plan.md)를 기준으로 한다.

여기서는 상위 흐름만 정의한다.

```text
phrase
-> archaicizePhrase(phrase)
-> GlyphToken[]
-> createGlyph(pool, index)
-> GlyphParticle
-> drawGlyph(glyph)
```

### 변환 원칙

- 입력창 텍스트는 현대어 그대로 유지한다.
- 출력 토큰만 옛한글풍으로 바꾼다.
- 변환 결과는 학술 번역이 아니라 시각 효과다.
- 같은 입력은 가능한 한 비슷한 출력 스타일을 만든다.

### 처리 단계

1. 입력 문장을 문자 단위로 순회한다.
2. 공백은 글자 풀에 넣지 않는다.
3. 현대 한글 완성형이면 초성, 중성, 종성으로 분해한다.
4. 중성 일부를 `ᆞ`, `ᆡ` 후보로 바꾼다.
5. 초성 일부를 `ᅀ`, `ᅌ`, `ᅙ`, `ᄫ` 후보로 바꾼다.
6. 종성 일부를 `ᇰ`, `ᇫ` 후보로 바꾼다.
7. 해시 기반으로 방점 개수를 정한다.
8. `{ text, tone }` 토큰을 반환한다.

### 한글이 아닌 문자

한글 음절이 아닌 문자는 그대로 토큰으로 만든다.

```js
{ text: character, tone: 0 }
```

이렇게 하면 숫자, 영문, 문장부호를 입력해도 화면이 깨지지 않는다.

## 11. 캔버스 렌더링 파이프라인

매 프레임 아래 순서로 실행한다.

```text
frame(now)
-> delta 계산
-> paused면 delta를 0으로 처리
-> sceneTime 갱신
-> drawBackground(time)
-> drawWillow(time)
-> updateAndDrawLeaves(delta, time)
-> 각 glyph에 대해 updateGlyph(delta, time)
-> drawGlyph(glyph, time)
-> requestAnimationFrame(frame)
```

### delta 처리

`delta`는 초 단위다.

```js
const rawDelta = Math.min((now - state.lastTime) / 1000, 0.035);
const delta = state.paused ? 0 : rawDelta;
```

상한을 두는 이유:

- 탭 전환 후 돌아왔을 때 입자가 갑자기 멀리 튀는 것을 막는다.
- 느린 기기에서도 움직임이 과격해지지 않게 한다.

### sceneTime

애니메이션 계산에는 `now`를 직접 쓰지 않고 `sceneTime`을 쓴다.

```js
state.sceneTime += delta * 1000;
```

이렇게 하면 일시정지 중에 달, 가지, 글자 흔들림이 모두 멈춘다.

## 12. 배경 렌더링

`drawBackground(time)` 역할:

- 전체 캔버스를 어두운 세로 그라데이션으로 채운다.
- 달 위치를 계산한다.
- 달빛 번짐을 radial gradient로 그린다.
- 달 본체를 원으로 그린다.

권장 값:

```text
moonX = width * 0.22 + sin(time * 0.00011) * 12
moonY = height * 0.2
moonRadius = clamp(width * 0.055, 42, 86)
```

달은 장면의 주인공이 아니라 분위기 요소다. 글자보다 시선을 빼앗으면 안 된다.

## 13. 능수버들 렌더링

`drawWillow(time)` 역할:

- 화면 오른쪽 근처에 줄기를 그린다.
- 줄기는 두꺼운 베지어 곡선으로 표현한다.
- 여러 개의 늘어진 가지를 반복문으로 그린다.
- 가지 끝이나 중간에 잎 무리를 붙인다.

권장 구조:

```text
trunkX = width * 0.68
trunkTop = -40
trunkBottom = height * 0.92
branchCount = width < 700 ? 13 : 19
```

가지마다:

- 좌우 방향을 번갈아 둔다.
- 시작 y를 조금씩 내린다.
- 길이와 reach를 다르게 둔다.
- time과 wind에 따라 sway를 적용한다.

주의:

- 가지 시작점에 매 프레임 랜덤을 쓰면 화면이 떨린다.
- 랜덤값은 생성 시 저장하거나, 인덱스 기반 결정값을 써야 한다.

## 14. 잎 렌더링

잎은 두 종류가 있다.

### 가지에 붙은 잎

`drawLeafCluster(x, y, seed, time)`에서 그린다.

- 가지 끝 주변에 작은 타원들을 배치한다.
- time에 따라 살짝 회전한다.
- 투명도를 낮게 유지한다.

### 떠다니는 잎 입자

`updateAndDrawLeaves(delta, time)`에서 갱신하고 그린다.

- 글자보다 작고 흐리다.
- 아래로 천천히 떨어진다.
- 바람에 따라 좌우로 움직인다.
- 화면 밖으로 나가면 위쪽에서 다시 시작한다.

잎 개수:

```text
max(36, glyphCount * 0.78)
```

## 15. 글자 입자 렌더링

`drawGlyph(glyph, time)` 역할:

1. 글자 흔들림 bob 계산
2. `context.save()`
3. 위치 이동
4. 회전 적용
5. 투명도 적용
6. 폰트 지정
7. 중앙 기준으로 글자 그리기
8. 방점 그리기
9. `context.restore()`

### 글자 위치

```text
x = glyph.x
y = glyph.y + sin(time * 0.002 + glyph.sway) * 8
```

### 글자 스타일

기본 글자:

```text
rgba(249, 242, 214, 0.78)
```

강조 글자:

```text
rgba(244, 201, 93, 0.66)
```

강조 글자는 전체의 약 25% 정도가 적당하다.

### 방점

방점은 `drawToneMarks(glyph)`가 그린다.

규칙:

- `tone === 0`: 아무것도 그리지 않는다.
- `tone === 1`: 글자 왼쪽 중앙에 점 하나
- `tone === 2`: 글자 왼쪽에 점 두 개

권장 위치:

```text
dotRadius = clamp(size * 0.055, 1.4, 3.2)
dotX = -size * 0.54
```

방점은 글자와 같은 회전 좌표계 안에서 그려야 한다.

## 16. 글자 입자 움직임

`updateGlyph(glyph, delta, time)` 역할:

- 바람에 따른 x 이동
- 입자별 좌우 흔들림
- y 낙하
- 회전
- 포인터 반발
- 화면 밖 재생성

### 기본 이동

```text
breeze = (wind - 0.5) * 40
sway = sin(time * 0.0017 + glyph.sway) * (10 + wind * 28)
x += (vx + breeze + sway * 0.04) * delta
y += vy * delta
rotation += spin * delta
```

### 포인터 반발

포인터가 활성화되어 있고 글자와의 거리가 150px 안이면 글자를 살짝 밀어낸다.

```text
force = (150 - distance) / 150
```

효과는 작아야 한다. 사용자가 글자를 조작한다기보다, 바람에 손을 대는 느낌이어야 한다.

### 화면 밖 처리

글자가 아래나 좌우 밖으로 나가면 위쪽에서 다시 생성한다.

조건:

```text
y > height + 80
x < -120
x > width + 120
```

재생성 시:

- 새로운 토큰을 고른다.
- x는 화면 안 랜덤
- y는 화면 위쪽 바깥
- 속도, 크기, 투명도, 회전값을 새로 준다.

## 19. 접근성

### 현재 목표

- 캔버스는 장식적/시각적 경험이므로 `aria-hidden="true"`로 둔다.
- 주요 조작은 HTML 입력 요소로 제공한다.
- `main`과 `section`에 적절한 `aria-label`을 둔다.
- 멈춤 버튼은 `aria-pressed`를 갱신한다.
- 키보드 포커스가 보이도록 `focus-visible` 스타일을 둔다.

### 주의

캔버스 안의 움직이는 글자는 스크린리더가 읽는 대상이 아니다. 입력 문장 자체는 textarea에 남아 있으므로 텍스트 정보는 유지된다.

## 20. 성능 기준

### 목표

- 데스크톱에서 부드러운 60fps에 가깝게 동작
- 모바일에서도 과하게 느려지지 않는 정도
- 외부 라이브러리 없이 즉시 실행

### 성능을 지키는 방법

- DPR은 최대 2로 제한한다.
- 글자 수 기본값은 100개 안팎으로 유지한다.
- 모바일에서는 밀도 상한을 낮출 수 있다.
- 매 프레임 새 객체를 대량 생성하지 않는다.
- 화면 밖 재생성 때만 새 속성을 만든다.
- 텍스트 변환은 입력 변경이나 재생성 때만 수행한다.

### 주의할 부분

캔버스 텍스트 렌더링은 생각보다 비용이 크다. 옛한글 조합 자모는 폰트 fallback 때문에 더 느릴 수 있으므로 글자 수를 무작정 늘리지 않는다.

## 21. 오류와 fallback

### 빈 입력

입력 문장이 비어 있으면 fallback 문자열을 사용한다.

```text
가나다라마바사아자차카타파하봄여름가을겨울달빛바람숲물결
```

### 한글이 아닌 입력

그 문자를 그대로 토큰으로 사용하고 방점은 붙이지 않는다.

### 폰트 문제

옛한글 조합 자모가 깨지면:

1. 폰트 후보를 늘린다.
2. 호환 자모 기반 fallback 모드를 추가한다.
3. 배포 시 옛한글 지원 웹폰트를 포함한다.

### Canvas 미지원

초기 버전에서는 별도 fallback 화면을 만들지 않아도 된다. 나중에 필요하면 canvas를 지원하지 않는 브라우저에 간단한 안내 문구를 제공한다.

## 23. 검증 체크리스트

### 실행 검증

- `index.html`을 브라우저에서 직접 열 수 있다.
- 콘솔에 치명적인 JavaScript 오류가 없다.
- `app.js`가 DOM 요소를 정상 참조한다.
- 캔버스가 화면 전체를 채운다.

### 시각 검증

- 배경이 어두운 밤 느낌이다.
- 달과 달빛이 보인다.
- 능수버들 줄기와 가지가 보인다.
- 잎이 천천히 움직인다.
- 한글 글자가 잎 사이로 흩날린다.
- 글자색이 배경과 충분히 대비된다.
- 방점이 글자와 붙어 보인다.
- 방점이 과하게 번지지 않는다.

### 입력 검증

- 문장을 바꾸면 캔버스 글자 구성이 바뀐다.
- 빈 문장에서도 fallback 글자가 나온다.
- 숫자나 영문을 입력해도 오류가 나지 않는다.
- 입력창의 문장이 자동 변환되지 않는다.

### 컨트롤 검증

- 바람 슬라이더가 움직임에 영향을 준다.
- 밀도 슬라이더가 입자 수에 영향을 준다.
- 멈춤 버튼이 장면 전체를 멈춘다.
- 멈춤 상태에서 버튼 텍스트와 `aria-pressed`가 바뀐다.
- 재시작 버튼이 장면을 새로 뿌린다.

### 반응형 검증

- 데스크톱에서 패널이 오른쪽 아래에 안정적으로 보인다.
- 모바일 폭에서 패널이 화면 밖으로 나가지 않는다.
- 버튼 텍스트가 버튼 밖으로 삐져나가지 않는다.
- 캔버스 글자가 모바일에서도 너무 많지 않다.

### 성능 검증

- 장면이 몇 초 뒤에도 계속 부드럽게 움직인다.
- 리사이즈 후에도 애니메이션이 이어진다.
- 밀도를 최대로 올려도 브라우저가 멈추지 않는다.

## 24. 구현 시 주의할 결정

### 결정 1: 무빌드 유지 여부

현재 방향은 무빌드 정적 웹앱이다.

장점:

- 바로 열 수 있다.
- 설정이 거의 없다.
- 작은 프로젝트에 맞다.

단점:

- 모듈 분리가 어렵다.
- 테스트 자동화가 제한된다.
- 규모가 커지면 파일이 길어진다.

초기 버전은 무빌드를 유지한다. 기능이 커지면 Vite 같은 도구 도입을 다시 판단한다.

### 결정 2: 중세국어풍 강도

너무 약하면 현대 한글과 차이가 작다.

너무 강하면 네모 박스, 낱자 분리, 가독성 저하가 생긴다.

초기 기본값은 아래가 적당하다.

```text
아래아 계열: 자주 사용
옛자음: 중간 정도
방점: 전체 글자의 35-45% 이하
현대 자모 유지: 항상 일부 남김
```

### 결정 3: 방점 구현 방식

초기 구현은 캔버스 직접 드로잉을 사용한다.

유니코드 방점 문자 `〮`, `〯`는 문서 예시나 fallback으로만 고려한다.

### 결정 4: 폰트 포함 여부

로컬 실행 단계에서는 시스템 폰트 fallback으로 충분하다.

배포 단계에서는 옛한글 지원 웹폰트를 포함할지 검토한다.

## 27. 구현자가 바로 따라갈 순서

1. `index.html`에서 캔버스와 컨트롤 패널 DOM을 만든다.
2. `styles.css`에서 전체 화면 레이아웃과 패널을 완성한다.
3. `app.js`에서 DOM 참조와 `state`를 만든다.
4. `resize()`로 캔버스 크기와 DPR을 처리한다.
5. `drawBackground()`와 `drawWillow()`로 정적인 장면을 만든다.
6. `createLeaf()`, `updateAndDrawLeaves()`로 잎 입자를 만든다.
7. `characterPool()`과 중세국어풍 변환 함수들을 만든다.
8. `createGlyph()`, `updateGlyph()`, `drawGlyph()`를 만든다.
9. `drawToneMarks()`를 연결한다.
10. `frame()` 루프를 만든다.
11. 입력, 바람, 밀도, 멈춤, 재시작 이벤트를 연결한다.
12. 모바일 레이아웃과 성능을 조정한다.
13. README와 문서를 갱신한다.

이 순서대로 가면 화면이 단계마다 살아나기 때문에, 어디서 문제가 생겼는지 확인하기 쉽다.
