# 중세국어풍 출력 설계 정리

## 목표

`hangul-willow`의 입력 문장은 현대 한국어 그대로 유지하고, 화면에 흩날리는 글자 출력만 중세국어풍으로 보이게 한다.

이 기능은 현대어를 실제 중세국어로 번역하는 기능이 아니다. 목적은 정확한 역사언어학 변환보다, 옛한글 자모와 방점의 시각적 인상을 활용해 작품 분위기를 만드는 것이다.

## 비목표

- 현대 한국어 문장을 문법적으로 정확한 중세국어 문장으로 번역하지 않는다.
- 단어별 역사 어형을 자동 추론하지 않는다.
- 모든 브라우저와 폰트에서 옛한글 조합 자모가 완벽히 보장되도록 별도 폰트 엔진을 만들지 않는다.
- 입력창의 텍스트를 강제로 옛한글로 바꾸지 않는다.

## 사용자 경험

사용자는 현대어 문장을 입력한다.

예:

```text
달빛 아래 한글이 바람을 따라 흐른다
```

입력창에는 이 문장이 그대로 남는다. 캔버스에 떠다니는 글자만 아래 요소를 섞어 중세국어풍으로 보인다.

- 아래아 계열: `ᆞ`, `ᆡ`
- 옛 자음 계열: `ᅀ`, `ᅌ`, `ᅙ`, `ᄫ`
- 종성 옛자모 계열: `ᇰ`, `ᇫ`
- 방점 느낌의 점: 글자 왼쪽에 1개 또는 2개

## 데이터 흐름

전체 흐름은 다음처럼 나눈다.

```text
사용자 입력
-> 공백 제거 및 문자 단위 순회
-> 현대 한글 음절 판별
-> 음절 분해
-> 중세국어풍 시각 토큰 생성
-> 글자 풀 생성
-> 캔버스 입자에 배정
-> 글자와 방점을 그리기
```

핵심은 "변환된 문자열"이 아니라 "그릴 토큰"을 만드는 것이다.

## 토큰 모델

캔버스에 들어가는 글자 하나는 단순 문자열보다 아래처럼 다루는 편이 좋다.

```js
{
  text: "ᄒᆞᆫ",
  tone: 1
}
```

필드 의미:

- `text`: 캔버스에 그릴 글자 또는 조합 자모 묶음
- `tone`: 방점 개수. `0`, `1`, `2` 중 하나

나중에 확장한다면 아래 필드를 추가할 수 있다.

- `source`: 원래 입력 글자
- `confidence`: 변환이 얼마나 장식적인지 표시
- `variant`: 어떤 규칙으로 만들어졌는지 표시

## 변환 규칙

### 1. 현대 한글 음절 분해

현대 한글 완성형 `가-힣`은 유니코드 계산으로 초성, 중성, 종성으로 분해할 수 있다.

```text
한 -> ᄒ + ᅡ + ᆫ
글 -> ᄀ + ᅳ + ᆯ
이 -> ᄋ + ᅵ
```

분해한 뒤, 중성이나 일부 자음을 옛한글풍 후보로 바꾼다.

### 2. 모음 장식

아래아 계열은 가장 중요한 시각 신호다.

예시 규칙:

```text
ᅡ -> ᆞ 후보 포함
ᅢ -> ᆡ 후보 포함
ᅥ -> ᆞ 후보 포함
ᅳ -> ᆞ 후보 포함
```

주의점:

이 규칙은 역사적으로 정확한 변환이 아니라 분위기 변환이다. 따라서 UI나 README에 "중세국어풍" 또는 "옛한글풍"이라고 표현하는 것이 안전하다.

### 3. 자음 장식

일부 초성은 옛자모 후보를 섞는다.

```text
ᄋ -> ᅌ
ᄉ -> ᅀ
ᄒ -> ᅙ
ᄇ -> ᄫ
```

권장 조건:

- `ᅀ`은 단어 첫 글자보다는 단어 내부에서 더 자주 쓰이게 한다.
- `ᄫ`은 너무 많이 쓰면 읽기 어려우므로 낮은 비율로 섞는다.
- `ᅙ`은 장식성이 강하므로 낮은 비율로 둔다.

### 4. 종성 장식

종성은 시각적 변화를 조금만 준다.

```text
ᆼ -> ᇰ
ᆺ -> ᇫ
```

종성을 많이 바꾸면 조합 자모 렌더링이 불안정할 수 있으므로 보수적으로 적용한다.

### 5. 방점

방점은 유니코드 문자 `〮`, `〯`를 문자열에 붙이는 방법과 캔버스에서 직접 점을 그리는 방법이 있다.

이 프로젝트에서는 캔버스 직접 드로잉을 우선한다.

이유:

- 폰트마다 방점 위치가 다르게 보일 수 있다.
- 글자가 회전할 때 방점도 같은 좌표계에서 자연스럽게 움직인다.
- 점 크기, 간격, 투명도를 입자 크기에 맞춰 조절하기 쉽다.

권장 비율:

```text
방점 없음: 약 55-65%
점 1개: 약 25-35%
점 2개: 약 5-15%
```

## 결정성

같은 입력이 매번 완전히 다르게 변하면 사용자가 조절하기 어렵다. 변환 후보 선택은 가능한 한 입력 글자와 위치를 기반으로 한 해시값을 사용한다.

```text
글자 + 전체 인덱스 + 단어 내 위치 -> seed
seed -> 후보 선택
```

이렇게 하면:

- 같은 문장은 비슷한 옛한글풍 결과를 낸다.
- 입자 위치와 움직임은 랜덤이어도 글자 스타일은 안정적이다.
- 나중에 테스트하기 쉽다.

## 렌더링 설계

### 화면 인상

첫 화면은 하나의 정적인 페이지라기보다 움직이는 밤 풍경처럼 보여야 한다.

구성:

- 전체 화면을 채우는 캔버스
- 어두운 녹색과 남색이 섞인 밤 배경
- 왼쪽 위 또는 화면 상단의 은은한 달
- 오른쪽 또는 상단에서 내려오는 능수버들 줄기와 가지
- 배경을 따라 천천히 떨어지는 잎
- 잎 사이로 흩날리는 중세국어풍 한글 토큰
- 오른쪽 아래 또는 모바일 하단에 놓이는 설정 패널

사용자가 보게 되는 글자는 완성된 문장이라기보다, 입력 문장에서 나온 음절 조각들이 바람에 흩어지는 모습이다.

예:

```text
ᄃᆞᆯ〮
비ᇫ
ᅌᆞ
ᄒᆞᆫ〯
ᄀᆞᆯ
ᄫᆞ
```

실제 구현에서는 `〮`, `〯` 문자를 붙이기보다 캔버스에서 점을 직접 그린다. 위 예시는 화면 인상을 설명하기 위한 표기다.

### 화면 레이어

캔버스는 아래 순서로 그린다.

```text
1. 배경 그라데이션
2. 달과 달빛 번짐
3. 능수버들 줄기
4. 늘어진 가지와 가지 끝 잎
5. 떠다니는 잎 입자
6. 중세국어풍 한글 입자
7. 한글 입자의 방점
8. HTML 설정 패널
```

HTML 설정 패널은 캔버스 안에 그리지 않는다. 캔버스 위에 별도 DOM으로 올린다. 이렇게 해야 입력창, 슬라이더, 버튼 접근성이 유지된다.

### 캔버스 크기

캔버스는 CSS 크기와 실제 픽셀 크기를 분리한다.

```text
CSS 크기: window.innerWidth x window.innerHeight
실제 픽셀 크기: CSS 크기 x devicePixelRatio
```

초기화와 리사이즈 때:

```text
canvas.width = width * dpr
canvas.height = height * dpr
context.setTransform(dpr, 0, 0, dpr, 0, 0)
```

이렇게 하면 고해상도 화면에서도 글자와 방점이 흐릿해지지 않는다.

### 폰트

옛한글 조합 자모는 폰트 지원 차이가 크다. 캔버스 폰트 후보는 여러 개를 둔다.

추천 후보:

```css
"HCR Batang", "함초롬바탕", "Noto Serif CJK KR", "Noto Serif KR", "Batang", "Malgun Gothic", serif
```

나중에 실제 배포를 목표로 한다면 웹폰트 포함 여부를 따로 결정해야 한다.

### 캔버스 그리기

글자는 기존 입자 시스템을 그대로 사용한다.

추가되는 것은 방점 드로잉뿐이다.

```text
context.fillText(token.text, 0, 0)
drawToneMarks(token.tone, glyph.size)
```

방점 위치:

- 글자 중심 기준 왼쪽
- 글자 크기에 비례한 점 반지름
- 점 2개일 때는 위아래로 균형 있게 배치

### 한글 입자 모델

한글 입자는 아래 정보를 가진다.

```js
{
  text: "ᄒᆞᆫ",
  tone: 1,
  x: 420,
  y: 180,
  size: 32,
  alpha: 0.72,
  rotation: 0.4,
  spin: -0.1,
  vx: 8,
  vy: 22,
  sway: 3.8,
  warm: false
}
```

화면에서는 이 입자 하나가 글자와 방점을 함께 가진 작은 오브젝트처럼 움직인다.

### 한글 입자 그리기 순서

입자 하나를 그릴 때는 아래 순서를 따른다.

```text
1. context.save()
2. 입자 위치로 translate
3. 입자 회전값으로 rotate
4. 투명도 적용
5. 폰트와 색 지정
6. text를 중앙 기준으로 fillText
7. tone 값에 따라 왼쪽에 점 1개 또는 2개 그리기
8. context.restore()
```

중요한 점은 방점을 글자와 같은 변환 좌표계 안에서 그린다는 것이다.

그래야:

- 글자가 회전하면 방점도 같이 회전한다.
- 글자가 흔들리면 방점도 같이 흔들린다.
- 글자와 방점 사이 간격이 유지된다.

### 방점 그리기

방점은 글자 크기에 비례해서 그린다.

권장값:

```text
dotRadius = glyph.size * 0.055
dotX = -glyph.size * 0.54
```

점 1개:

```text
(dotX, 0)
```

점 2개:

```text
(dotX, -dotRadius * 1.85)
(dotX,  dotRadius * 1.85)
```

색은 글자색과 같게 하고, 그림자는 줄이거나 끈다. 방점까지 강한 그림자가 들어가면 점이 번져서 지저분해 보일 수 있다.

### 움직임

중세국어풍 글자는 잎보다 조금 더 느리고 무겁게 움직이는 편이 좋다.

기본 움직임:

```text
x += 바람 + 좌우 흔들림
y += 천천히 떨어지는 속도
rotation += 미세한 회전
```

시각적 목표:

- 글자가 종이 조각이나 버들잎처럼 가볍게 떠야 한다.
- 너무 빠르게 떨어지면 문자를 읽을 수 없다.
- 너무 많이 회전하면 옛자모 형태가 무너져 보인다.

권장 범위:

```text
size: 17-52px
alpha: 0.34-0.92
vy: 12-46px/s
spin: -0.7 to 0.7 rad/s
```

### 화면에서의 밀도

글자가 너무 많으면 옛한글의 낯선 모양이 노이즈처럼 보인다.

권장 기본값:

```text
데스크톱: 80-110개
모바일: 45-75개
```

밀도 슬라이더가 있더라도, 모바일에서는 내부적으로 상한을 낮추는 것이 좋다.

### 글자와 배경의 대비

글자색은 완전한 흰색보다 따뜻한 종이색이 좋다.

추천:

```text
기본 글자: rgba(249, 242, 214, 0.78)
강조 글자: rgba(244, 201, 93, 0.66)
```

글자 그림자는 약하게만 준다. 강한 그림자는 옛자모 획을 뭉개 보이게 한다.

### 폰트 실패 대비

옛한글 조합 자모가 네모 박스나 분리된 낱자처럼 보일 수 있다.

대응 단계:

1. 여러 한글 폰트를 fallback으로 둔다.
2. 그래도 깨지면 조합 자모 대신 호환 자모 중심의 장식 모드를 둔다.
3. 배포 단계에서는 옛한글 지원 웹폰트를 포함할지 결정한다.

fallback 장식 모드 예:

```text
ᄒᆞᆫ -> ㅎㆍㄴ
ᅌᆞ -> ㆁㆍ
ᅀᅵ -> ㅿㅣ
```

이 방식은 조합형 음절처럼 예쁘게 붙지는 않지만, 글자가 깨지는 것보다는 낫다.

## UI 설계

지금은 출력이 항상 중세국어풍이어도 된다.

나중에 옵션을 넣는다면 아래 정도가 적당하다.

- 출력 방식: `현대 한글`, `중세국어풍`
- 방점: 켬/끔
- 옛자모 강도: 낮음/보통/높음

단, v0에서는 컨트롤을 늘리기보다 기본 분위기를 잘 잡는 편이 낫다.

## 구현 단위

구현은 아래 순서가 가장 안전하다.

1. `characterPool()`이 문자열 배열 대신 토큰 배열을 반환하도록 바꾼다.
2. 현대 한글 음절 분해 함수를 만든다.
3. `archaicizeCharacter()`를 만들어 한 글자를 토큰으로 변환한다.
4. `createGlyph()`가 `text`와 `tone`을 함께 받도록 바꾼다.
5. `drawGlyph()`에서 글자를 그리고, 이어서 `drawToneMarks()`를 호출한다.
6. 입력 변경, 밀도 변경, 리셋 시 기존처럼 `seedScene()`만 다시 호출한다.

## 테스트 체크리스트

- 현대어 입력창의 텍스트가 바뀌지 않는다.
- 캔버스 글자에 `ᆞ`, `ᅀ`, `ᅌ` 같은 옛한글풍 요소가 보인다.
- 방점이 글자 왼쪽에 자연스럽게 붙는다.
- 글자가 회전할 때 방점도 같이 회전한다.
- 입력 문장을 바꾸면 글자 풀이 다시 만들어진다.
- 한글이 아닌 문자도 깨지지 않고 그대로 나온다.
- 모바일에서 패널과 캔버스 글자가 겹쳐도 조작이 가능하다.

## 향후 고도화

### 사전 기반 후보

작품 분위기보다 정확도를 올리고 싶다면 로컬 사전을 추가한다.

예:

```js
{
  "하늘": ["하ᄂᆞᆯ"],
  "바람": ["ᄇᆞ람"],
  "사람": ["사ᄅᆞᆷ"]
}
```

다만 이 단계부터는 "출력만 중세국어처럼"의 가벼움이 줄어든다.

### 프리셋

표현 강도를 프리셋으로 나눌 수 있다.

```text
은은함: 아래아와 방점만 약하게
고문헌풍: 옛자모와 방점을 적극 사용
가독성 우선: 현대 음절 비율을 높임
```

### 폰트 내장

배포 시 옛한글 조합 자모 렌더링이 불안정하면 웹폰트를 포함한다. 이 경우 라이선스 확인이 필요하다.

## 요약

이 기능의 핵심은 번역기가 아니라 출력 스타일러다.

현대 입력을 보존하고, 캔버스 입자에 들어가는 글자만 옛한글 조합 자모와 방점이 포함된 토큰으로 바꾼다. 이 구조를 유지하면 현재 작품성은 빠르게 살릴 수 있고, 나중에 사전 기반 정확도나 UI 옵션을 추가하기도 쉽다.
